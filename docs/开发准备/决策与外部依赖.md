# 决策与外部依赖

日期：2026-09-15。来源：现有 01–06 与本轮用户授权。以下为可修订的开发设计，不改变产品首版范围。

## 1. 本轮采用的决定

| 编号 | 决定 | 理由与影响 |
| --- | --- | --- |
| D01 | 提前完成 T02–T14 设计，实际代码仍逐模块交付 | 用户明确要求准备模块需求、接口、数据和示例；避免一次写全部应用 |
| D02 | 所有业务 HTTP 沿用 T01 的 `{requestId,data}` / `{requestId,error}` | 消除旧文档 value/data 描述差异；业务提交版本放在 data 内 |
| D03 | 写命令统一 clientOperationId + expectedRevision；项目会话在请求头 | 区分请求追踪、业务防重和项目访问权限；响应丢失可查原操作 |
| D04 | 持久化关系用 SQLite；内容 payload 用带类型的 JSON Schema | SQL 负责关系与唯一性，Schema 负责内容结构，语义规则由后端用例负责 |
| D05 | 首轮工程验证平台 Windows 11 x64；不提前承诺其他平台 | 已有 T01 基线如此规定；真实运行时依赖安装验证，不擅改候选版本 |
| D06 | 默认 1080p/24fps，展示 30 秒/七镜研究规模 | 沿用原产品规格；该规模不是产品最大长度，也不意味着写实效果已验证 |
| D07 | 支持本地音频/视频导入，真实云能力按档案逐项启用 | 可以用固定素材开发，不用未验证模型充当生产默认 |
| D08 | 代表镜头研究沿用“写实、中文单人对白、简单接触、跨镜身份” | 与既有目标一致；复杂打斗、群像及高难长镜不作为首轮通过前提 |
| D09 | 原型使用本地中文系统字体、普通 CSS、低饱和深色工作台 | 避免远程资源；按任务组织界面，不采用营销首页布局 |
| D10 | 模型生成/审核/音乐音效全部走同一个有界任务服务 | 各模块不能自建直接收费入口，防止重复授权与账目分裂 |
| D11 | 时间线编辑先保存草稿，经本地影响预览后采用；所有视图共享一个版本 | 不用界面状态直接修改已确认成片；长时间渲染绑定快照 |
| D12 | 用 synthetic 夹具补工程验证输入，历史文件缺失保持事实 | 可开始研发，又不伪造原模型请求、真人结论或账单 |

## 2. 仍需外部证据，但不阻止基础开发

| 项目 | 当前处理 | 必须解决的时机 | 需要的输入 |
| --- | --- | --- | --- |
| 用户最终认可的写实动态效果 | 以已有视觉参考制定暂定评审卡，不宣布通过 | 首次真实代表镜头采用及发布定级前 | 可播放参考片段或用户对新试片的实际反馈 |
| 生产模型与账户 | 能力关闭；用假服务和导入素材开发 | 对应真实调用前 | 账户可用性、型号/地域、价格、协议和能力实测；Key 只在本机配置 |
| 收费研究预算 | 本轮不进行收费推理或上传 | 第一次真实收费研究前 | 用户对具体镜头、次数、费用上限的授权；“全程交给你”不推断无限消费额度 |
| 旧 `.local` 研究原件 | 标缺失，保留现有副本与证据索引 | 复核历史测试、复用原脚本前 | 原工作区导出的脱敏材料；找不回时重新设计新实验并独立记账 |
| 新手与独立评审 | 提供脚本、评分表和招募条件，不代替真人填写 | G00 使用者走查及 T14 | 真实参与者、观察记录和独立判断 |
| 分发签名与素材许可 | 内部目录包与自带合成示例优先 | 对外分发前 | 证书与主体信息、运行时/依赖和内置素材许可证据 |

## 3. 什么时候找用户确认

仅在必须选择不可由现有资料推导的方向时确认：动态效果喜好产生实质分歧；新增服务商/付费预算；必须改变已确定首版范围；需要用户持有的参考或授权证据；需要安排真人试用。接口命名、数据库索引、错误码、测试示例和普通布局由开发设计自主决定。

资料完备不等于技术可行性已获证实。进入开发可以获得前面未知项所需的工具，但相应发布关口一直保留。
