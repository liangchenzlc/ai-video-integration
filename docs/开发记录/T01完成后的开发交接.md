## 1. 先明确当前交付是什么

这是面向中文新手的 Windows 本地 AI 短剧制作工具，用户自行配置 API Key，项目与素材保存在本机。计划工作流为故事 → 视觉资产/分镜 → 配音与关键帧 → 静态预演 → 逐镜视频 → 时间线/混音 → 检查/MP4。首版质量优先于成本，成本优先于效率；写实电影感是正式效果目标，已有二维研究素材不算质量验收通过。

T01 交付桌面底座：能打开真实 Electron 窗口，看到真实后端状态，重启本地服务，浏览六组导航与设置，正常关闭并清理所属后端。业务区域明确显示尚未开放。

**尚不能创建项目、保存草稿、导入媒体、配置 Key、调用模型、剪辑或导出。T02–T14 的需求/接口/数据模型文档已经存在，应用实现均未完成。** 不要把设计 JSON、研究脚本、G00 原型或目录包能启动当成这些功能已完成。

本次没有真实模型调用，没有生成费用，没有创建 Git 提交。工作区此前已有未提交文档，接手时先查看差异，不要重置或覆盖它们。

## 3. 如何运行、检查与打包

所有命令从项目根 `D:\code\ai-video-integration` 执行。当前机器工具已安装在项目内部，不依赖系统全局 Python/Node。

```powershell
# 开发窗口，固定 127.0.0.1:5173，端口占用时应明确失败
powershell.exe -NoProfile -File scripts/dev.ps1

# 契约、两端检查/测试、构建、真实桌面测试
powershell.exe -NoProfile -File scripts/check.ps1

# 无桌面条件下只做代码检查；此命令不代表完整验收通过
powershell.exe -NoProfile -File scripts/check.ps1 -SkipDesktop

# Windows x64 目录包
powershell.exe -NoProfile -File scripts/pack-win.ps1

# 复制到新的中文/空格目录，再测目录包及故障清理
powershell.exe -NoProfile -File scripts/test-packaged.ps1
```

可执行文件位于 `release/t01/win-unpacked/AI Video Integration.exe`。必须保留整个 `win-unpacked` 目录，尤其是 `resources/backend/` 和 Electron 运行文件；不能只复制 exe。这是本机工程目录包，不是 T13 的签名安装器，也未承诺其他 Windows 版本可用。

已有固定工具：`.tools/node/node.exe`、`.tools/bin/pnpm.cmd`、`.tools/uv/uv.exe`、`backend/.venv/Scripts/python.exe`。准确版本见 `docs/技术方案/契约/t01-toolchain-baseline.json` 和 `docs/开发记录/t01-a-toolchain.json`。项目 Node 为 24.21.0；Electron 自带 Node 版本另由目录包实测记录，两者不要求相同。

换机器时先阅读 `scripts/bootstrap_toolchain.py` 与 `scripts/verify_toolchain.py`，安装固定版本，再按 `backend/uv.lock` 与 `frontend/pnpm-lock.yaml` 做 frozen 安装。不要执行 `latest` 升级，也不要删除锁文件来绕过问题。当前首次安装的工具目录不纳入 Git。

### 环境注意事项

- Windows venv 的 `python.exe` 是重定向启动器，会多出一个 PID。正式开发启动使用 `.venv/pyvenv.cfg` 的实际 CPython 加受控 `__PYVENV_LAUNCHER__`，详见 `launch.ts` 和 `python_launch.py`；不要改回直接 `uv run` 或 venv exe 后声称 PID 相等。
- PyInstaller 必须 `onedir + console=True` 保留标准流；窗口隐藏由父进程控制。后端在 asar 外。
- 当前执行沙箱会拒绝部分 Node 文件写入或 Electron 渲染器启动。已在正常 Windows 权限下验证，Electron 自身的 sandbox 始终开启。不要用 `--no-sandbox` 修复执行环境问题。
- pytest 使用 `-p no:cacheprovider` 避开当前沙箱下缓存目录创建挂起，不跳过测试。
- Vitest 的临时用户数据放 `.cache/vitest-userdata`。不要打印或提交该目录中的工具令牌。测试脚本会还原环境变量。
- Electron 的下载在此机使用过镜像，保留官方 SHA256 检查；打包直接复用已验证的本地 Electron dist。无需每次下载。
- `.cache`、`release`、`frontend/out`、`backend/dist` 均为产物，可重建。删除时只针对已核对的项目内部路径，不清理用户项目/媒体。

## 5. T02：下一步的具体实施方案

依据 [T02 设计](../技术方案/模块设计/T02-项目数据库媒体和恢复.md)，分三批，每批都有可演示结果。

### 第一批：创建、打开与恢复

1. 建立后端 `storage/`、`services/projects.py`、项目路由与 DTO；文件名可调整，职责要分清。
2. 编写生产迁移 002，只创建 projects、operations、drafts、media_files、import_intents、local_jobs。应用库只落本批需要的 global_operations/最近项目等，不提前创建任务、费用和版本表。
3. 统一连接工厂：foreign_keys=ON、WAL、synchronous=FULL、busy_timeout=3000 ms；写事务短小，禁止在事务内等待网络/复制大文件。
4. 先实现 main 原生目录选择与一次性 file grant。grant 绑定用途/窗口/会话与五分钟 TTL，经 main 私有 HTTP 登记；renderer 只拿 grantId，不拿路径。
5. 创建按跨库恢复协议执行：应用操作 prepared → 目标标记和 staging → 完整项目库刷盘/发布 → global operation committed。同 operationId 重试返回同项目；无法判定的残留保留并提示。
6. 打开时处理可移动目录、项目 OS 写锁、read/write 会话、损坏库与拒绝写入的网络/同步目录。单实例桌面和项目写锁不是一回事；后续多窗口需扩展当前单窗口 sender 注册，不能关闭单实例锁来代替项目会话设计。
7. 首页增加真实新建/打开/最近项目，未配模型也可创建本地草稿。

验证：重复创建仅一次、同 ID 不同内容 409、非空非项目目录不覆盖、创建各中断点可恢复、移动目录可重开、第二写请求只读、损坏库不被重建覆盖。使用真实临时 SQLite 与目录，不以 mock 提交成功代替落盘证据。

### 第二批：草稿与可靠保存

1. PUT/GET draft，严格 clientOperationId/expectedRevision、完整 UTF-8 正文与 SHA256，身份、会话、对象归属校验。
2. 认证之后先查已有操作，再做 CAS、grant 和状态校验。正文写入、revision+1、operation receipt 同事务。
3. 前端防抖 800 ms，切换对象/关闭先 flush；只在提交成功显示保存时间，失败保留编辑输入。
4. 响应丢失查询原 operation，不自动换 ID 重写。CAS 冲突给出已保存文本与本地输入，不隐式覆盖。

验证：两个编辑者旧 revision 冲突、同长度改字仍产生新内容 hash、同请求重放不重复递增、断开与重新打开不丢输入/已存稿。保存草稿不等于采用，不提前传播下游失效。

### 第三批：媒体和本地作业

1. 落实 FFmpeg/ffprobe 固定发行版本、来源与许可，再接流式复制、staging、哈希、类型/解码探测、同盘原子改名、登记。
2. 导入 intent 和 local job 持久化；改名后登记前崩溃，可按 intent+hash 补登记；未知孤件隔离，不自动删除。
3. 实现有界 Range 媒体读取以及有限 `app-media` 协议代理；只按媒体 ID/项目会话解析，不开放 file 路径。
4. 缺失文件重新定位须同 hash 保留 mediaId；不同 hash 是新导入/替换。源文件默认复制，不移动用户原件。
5. 加磁盘余量和大小/解码保护：初值 2 GiB、40 MP、ffprobe 15 秒；实测后再调整并记录。

验证：磁盘不足、权限拒绝、超限/损坏媒体、路径穿越/junction、Range、取消、复制/改名/登记各中断点、同名不同 hash、WAL 活跃时迁移 backup 副本可读。最后演示“创建 → 输入 → 保存 → 导入 → 关闭 → 重开”。

## 6. T03–T14 尚未做什么、怎样推进

### T03 凭据、能力与完整配置

实现后端用户范围 DPAPI、应用配置库、设置版本与能力档案。已保存 Key 永不回传到 renderer/项目/日志，用户提交后清空输入。细分阶段分别配模型，不强制一套模型覆盖故事所有步骤。区分连接成功、账户可用、效果验证通过；还要覆盖地域权限、音色、传输与 FFmpeg，不只放一个 Key 输入框。

验证加密失败、删除/失效、地域/型号错误、设置重开、全错误路径秘密哨兵。先用本地假服务；真实连接或计费验证需要明确凭据与授权。

### T04 任务、费用与恢复

先做本地 planTask，再做持久化 startTask 和单主动执行槽。计划绑定输入版本/hash、能力/价格/模板版本、step/candidate 上限、三重预算与十分钟有效期。prepared、submitting、unknown、已知 ID/下载分开落盘。任务与本地媒体作业分表。

金额是整数 microCny；reserved 与 settled 替换计入，不叠加。防重记录和授权同事务。测试受理后断网/退出、返回 ID 前后崩溃、部分候选失败、重复结算、预算耗尽仍取回原结果。unknown 不能重新 POST，停止等待不冒称云端取消。

### T05 版本采用、依赖与撤销

增加不可变 revisions、artifact 指针、依赖边、检查基准、采用/撤销事务。明确选中、采用、确认的区别。采用预览显示影响，仅真正依赖交叉才被执行中任务锁住。撤销恢复映射/确认基准，保留所有新媒体、调用和费用。

验证角色改色与台词/字幕各自传播范围、同长度改字、无关草稿不阻塞、短素材替换、重排及撤销。不要以“重新运行整条流水线”实现局部修改。

### T06 文字、图像与结果取回

按确切服务商地域、接口、模型档位与参考用途编译适配请求；所有收费调用经过 T04。结构化结果严格解析，保留候选与用量。下载经过来源/重定向/大小/类型/hash/解码检查，失败只恢复原下载。输入参考不支持时明确阻止，不能静默忽略。

先用固定响应覆盖成功、部分结果、错误/断网与恶意下载 URL；真实文本/图像样本另经费用授权。API 200 不等于质量通过。

### T07 故事、资产与分镜

实现三种故事入口与原文/改编差异、来源范围/必留要求、资产、镜头卡与稳定 ShotId。把已存在的领域案例用于验证人物、动作、唯一道具、台词、起止状态与揭示。自然语言修改先显示草稿/影响，再决定采用；不自动收费或全片重做。

验证镜头重排归属不变、必须事件不丢、身份与姿态分离、四类关键帧用途、参考缺失出口。使用静态/假模型先完成可操作工作流，艺术质量另验。

### T08 配音、字幕与时间容量

先导入真实音频与探测时长，再接已确认的语音型号/音色；试听计费明确。句级/人工定时和字级时间戳标明精度。台词、配音、字幕是独立版本与依赖。

验证 5.2 秒发声加前后 0.6 秒无法放入 6 秒，不自动加速删词；字幕改字不重生成配音，转写不覆盖已采用台词，配音变更使相关字幕/对白视频待更新。

### T09 静态预演与基础时间线

实现统一 Timeline/RenderPlan 语义，图片/视频/配音/音乐/音效/字幕轨、入出点、移动/分割、吸附、硬切/叠化与基础关键帧。预览、预演和最终导出共用状态，但仍要实测同步误差与编码结果。

以七镜夹具导出 30 秒预演，用 ffprobe/完整解码验证。测试 5 秒片段替换成 3 秒时的缺口、镜头移动携带字幕/台词、半开区间和统一帧量化，不拉伸/冻结补洞。

### T10 动态视频、对白与稳定传输

新增确切视频模型能力和输入准入、时长/尺寸/audio/shot_type、首尾帧/多参考组合，复用任务与下载恢复。生产音频传输要有正式 OSS 或已核准替代，保存上传/远端关联，运行中不删除输入。

故障测试仍用假服务；真实效果验证 S03 口型/身份、S04 左手放灯松手、多人物声源与时序。缺能力时不能改旁白、藏嘴或跳切后宣称原目标通过。

### T11 音乐、音效与混音

先实现本地素材导入/许可证据、裁切/循环、音量/淡入淡出、对白优先混音，再单独核验 AI 音乐/音效供应商能力、价格和商用条件。更换音乐不重生成画面。

测削波、静音缺口、重复音轨、对白遮挡与循环边界。AI 分支没有证据时保留缺口，不以本地导入冒充 AI 功能已完成。

### T12 检查、修订与正式导出

实现 check_runs/check_reports 与 issues 的区别，绑定具体版本、规则、基准、已观察范围和证据。只检查当前采用链；无报告不能因问题表为空判为通过。普通偏差可带理由接受，必要风险须补证/复检。

冻结输出快照，编译 H.264/AAC MP4 与字幕开关，保留导出作业/原文件。验证预览一致性、完整解码、分辨率/帧率/时长、失败不自动收费修复、废弃候选不误拦导出。

### T13 安装、升级与诊断

当前只有 x64 目录包。后续做发行清单、安装器、签名/许可/第三方声明、干净 Windows 安装、升级前完整备份、失败回退、卸载保留用户数据。诊断包白名单收集并做秘密扫描，不直接压缩整个用户目录。

验证无开发 Python/Node 的干净机器、低权限/路径/升级中断、旧项目迁移、应用目录只读与诊断边界。最终签名、发布和外部分发需在具体产物完成后按用户授权执行。

### T14 发布验收与组合定级

执行完整样片闭环、真实质量/费用的配对比较、模型组合定级与至少五名新手试用。工程可跑、API 成功、内部原型走查都不能替代这一关。

招募参与者、确定真实调用预算/账户/效果标准，记录失败和不可用组合。产品目标若需缩减，应明确请用户决定，不能通过修改文档把未实现功能删掉来“完成”。

## 7. 必须保留的系统约束

- renderer 无 Node、无任意 IPC/HTTP、无令牌/后端端口、无已保存 Key/绝对磁盘路径。固定桥逐项扩展并验证。
- main → supervisor → API → 媒体子进程；supervisor 持唯一不可继承 Job 句柄。不得杀全局 python/ffmpeg，不按历史 PID 清理。
- ready 必须先通过管道身份与认证健康。关闭优先，旧 child/runtimeId/generation 回调全部失效；正常停止需要 stopped 与真正退出，stop_ack 不够。
- 30 秒启动，HTTP 单次 1500 ms、启动重查 500 ms，稳态 5 秒、三次瞬态失败断开，认证失败立即断开。停止 5 秒宽限+2 秒清理，main 最终 8 秒；STOP_TIMEOUT 禁止就地重启。
- operationId 是业务防重；requestId 只是诊断。写操作 CAS、操作回执与数据同事务；后台进度不不断增加编辑 revision。
- 选中/保存草稿/采用/确认不同；撤销不退费，不删除生成原件。费用事实和结果质量分别保存。
- 一次主动任务只处理一个对象/阶段；无自动付费重试、无跨阶段自动生成、无 unknown 重发。恢复旧结果不能变为新增生成。
- 原件、已发生费用和用户输入优先保留。研究素材、模拟费用和假服务必须明确标识。

## 8. 哪些问题才需要找用户确认

常规目录划分、类型/事务实现、故障修复、离线测试可按现有授权自行完成。真正需要确认的包括：真实服务凭据及计费预算、产品范围改变、已有方案实测不能达标时的效果/成本取舍、真人试用参与者和发布分发。

当前 T02 第一批没有阻塞性产品问题，可直接依据现有设计实施。后续发现文档互相冲突时先定位负责该规则的产品/契约文件，给出具体选项和影响，不把所有工程选择都推给用户。

## 9. 每批次完成后如何交接

记录本批改变的用户行为、具体文件/契约/迁移、真实执行的命令与退出码、关键故障案例、Review 发现与修复、未通过项及下一批入口。Review 是实现者自查时明确写自查，不能称独立审查。

仅勾选实际通过的 [原任务清单](../05-开发计划与验收标准.md)，并同步能力表、导出契约和类型。交接应能回答“从哪个文件开始、输入输出是什么、如何证明正确、出了错保留什么”，不只写“继续完善”。
