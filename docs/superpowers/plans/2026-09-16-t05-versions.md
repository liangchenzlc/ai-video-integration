# T05 版本、采用、依赖与撤销实施计划

> **For agentic workers:** Use superpowers:subagent-driven-development to execute task by task. T04 验证与审查通过后开始实现。

**目标：** 草稿和候选不改变当前作品；采用经过可核对的影响预览，以短事务同时更新当前版本和相关下游；撤销保留新候选、媒体和全部消费。

**依据：** T05 模块设计、跨模块约定的版本/检查规则、完整 TypedPayload 和设计 SQL。用户已确认空白/未完成草稿允许保存，采用、确认和生成必须校验所需完整性。

## 设计约束与集成决策

- 选中只在 UI；draft 可不完整；正式 revision 不可变，同对象 parent/adopted/confirmed 使用复合外键。完整性不等于生成质量通过。
- 建立 005 迁移：artifacts/revisions/revision_media/dependencies/task_inputs/adoptions；继续写前一致备份、身份校验、失败回滚与只读不升级。
- 当前契约缺少“当前采用/确认/待更新”的读取接口，补 `GET /projects/{projectId}/artifacts/{artifactId}`，返回 `{id,kind,adoptedRevisionId,confirmedRevisionId,needsUpdate,latestAdoptionId}`。列表候选不能靠顺序猜当前采用。latestAdoptionId 仅在全项目最近未撤销采用属于该对象时返回 ID，否则为 null；重开可继续撤销，实际执行仍校验冲突。
- 影响预览五分钟有效，绑定 session/project/revision/artifact/toRevision/hash；只读计算，不调用模型。采用时重新校验，同一操作重放先于预览过期判断。
- 语义依赖以实际版本引用为依据，from 上游、to 下游，禁止环。未确定的变化保留核对义务。未采用候选不改下游状态。
- T04 任务接入正式 inputRevisionIds 和 task_inputs；冻结完整版本快照，任务活动时阻止改变其输入的采用，仍允许草稿保存和无关对象采用。已提交候选结果仍保留。
- 采用确认依赖有效 CheckReport，不能从“问题表为空”推断通过。为兑现 T05 确认流程，提前实现 T12 的最小确定性结构检查入口和 check_runs/checks 表；仅支持明确版本的本地结构/引用规则，完整 T12 仍待实现，绝不伪造语义、审美或真人结果。
- 已有故事编辑器只写原文/入口/简报；正式 proposal 可规范补全空集合与 proposal 层级，必须保留用户原文并按原字节计算 sourceHash，不凭空产生场景、对白或必留要求。完整结构仍按 TypedPayload 验证。
- 撤销仅最近未撤销采用，采用之后对同关联的修改导致冲突；按关联快照恢复，不能整库回退。费用、调用、新候选和媒体不在撤销写集内。
- 正式版本 canonical UTF-8 内容最多 700 KiB，超限返回 `REVISION_SIZE_LIMIT` 422 并保留草稿；版本页同时受 200 条和 800 KiB 内容预算约束，继续使用 UUID 游标。草稿保存上限不变，桥与业务响应仍为 1 MiB。
- 最小本地检查规则固定为 `structural`、`references`，版本 `local-structure-v1`；请求的版本与规则列表均不得为空。报告只证明结构与引用检查，不代表剧情、视听质量或人工验收。

- [x] createRevision 从指定 draft 创建稳定候选，登记 artifact，拒绝跨对象 parent 和更改 kind；操作重放/CAS/只读/窗口归属完整。
- [x] getArtifact、listRevisions（UUID cursor）、必要的单版本服务读取，返回安全字段。
- [x] revision 不可变触发器及 revision_media 索引；事务中断不留半个 artifact。
- [x] 相同长度原文改字产生不同 sourceHash/contentHash；草稿和候选均不自动采用。
- [x] 迁移 004→005、安全备份/失败回滚/身份替换/未来版本拒绝回归。

## Task 2：影响、采用、语义传播与撤销

- [x] 根据 TypedPayload 中稳定 revision 引用创建语义边；DFS/拓扑检测环与跨对象错误。
- [x] previewAdoption 返回旧/新版本、实际下游对象/范围、必要检查及未知额外费用，未变化项可由 UI 对照完整内容。

## Task 3：必要结构检查与明确确认

文件：最小 local-check service、检查表/DTO、确认校验、tests。

- [x] local-checks 只运行确定性规则并持久化 CheckReport，引用具体 revision、规则版本和范围；不自动发起 AI。
- [x] 零问题仍必须存在 pass report；unknown/fail 不当成 pass，不适用规则记录 not_applicable。
- [x] confirmRevision 只能确认当前采用版本，checkIds 必须覆盖当前版本必要规则；旧版本报告不可复用。
- [x] 采用并确认复用有效报告；必要检查缺失时 UI 可采用并待审核，不能假确认。
