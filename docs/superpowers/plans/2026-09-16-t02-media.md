# T02-C 媒体导入、访问与恢复

> **For agentic workers:** Use superpowers:subagent-driven-development to execute task by task.

**目标：** 真实图片/音视频安全复制进项目，可移动、可播放、可查作业；任何中断不删除唯一原件。

**依据：** T02 设计、跨模块契约、V02-02/04/05/06；沿用 SQLite 六表。媒体白名单 PNG/JPEG、MP4、WAV、MP3、M4A；2GiB、40MP、ffprobe 15s、空间余量 10%+256MiB。使用用户本机工具，不随应用分发 FFmpeg。

## 依赖裁定

T02 的真实探测依赖 T03 的媒体工具设置。因此提前实现 T03 已设计的 `settings` 单例表、FFmpeg 原生授权与 `configureMediaTools`，其余凭据/能力仍在 T03。不得以 PATH 自动发现或研究目录硬编码代替用户配置。现有 `.local` 的 FFmpeg 只作测试夹具工具路径。

## Task 1：工具与媒体后端

- 增加安全文件 grant（importMedia/ffmpeg），保持一次性、窗口归属、真实路径检查。
- 工具配置用 settingsRevision CAS 和全局 operation 幂等；检查配对 ffprobe、版本、H.264/AAC/libass 能力；摘要不含路径。执行固定 argv，不经 shell；超时、输出上限、协议白名单。
- 导入先在短事务写 accepted receipt/local_job/import_intent 快照，再单执行器流式复制/哈希/fsync，探测与解码，记录 verified，再原子改名、登记 available。IO 阶段不得占用保存事务。
- 作业和来源路径留后端；取消保留输入和已有文件，不虚报 succeeded。窗口关闭期间执行器仍须持有写锁，退出可恢复。
- 恢复只补登记 verified/renamed 且 hash 一致的产物；未知/部分文件保留并隔离，不根据名称删除。
- get/list media、get/cancel job、重新定位同 hash 保持 mediaId；异 hash 拒绝并引导新导入。
- backup API 在活动 WAL 下创建唯一副本、完整性/外键检查，失败保留旧库和副本，不原地迁移。
- 测试先行：真实 FFmpeg 媒体、非法格式/超量/空间不足、重放、只读拒绝、复制中断、改名后崩溃、取消、移目录、缺失、异 hash、活动 WAL 备份。

## Task 2：API/桌面媒体闭环

- 有限导入/作业/媒体/重新定位路由、DTO、session 绑定；原路径不回传 renderer。
- 有界二进制 GET/Range：单范围、206/416、类型与长度、HEAD；不能把任意 URL/文件路径传入桥。
- Electron 固定媒体 scheme 只允许当前项目 mediaId，main 代理认证与 Range，CSP 增量许可媒体来源；renderer 不得见 bearer/端口/源路径。
- 原生选择本机工具/素材；前端展示准备→复制/校验→完成/失败/取消，并能查询原操作，失败不自动另建导入。
- 媒体列表、图片/音视频预览、missing 重新定位；媒体准备独立于模型费用。
- 真实桌面配置工具→导入→预览→关闭→移动→重开；错误路径与 T01/T02 草稿回归。

## 完成门槛

覆盖测试、静态检查、真实后端/桌面证据、独立 Review、更新交接。工具验证仅说明本地编解码能力，不标记模型或成片质量通过。
