# T02-B 可靠草稿与自动保存实施计划

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development or superpowers:executing-plans to implement this plan task-by-task.

**Goal:** 编辑原文时保存完整输入；中断、冲突和响应丢失不丢稿、不重复递增。

**Architecture:** 服务在项目 OS 写锁和短 SQLite 事务内保存正文、project revision、operation receipt。DraftPayload 容许未完成内容，正式 TypedPayload 维持完整性约束。Electron 桥处理固定项目草稿命令；渲染层以 800ms 防抖、单次提交和原 operation 查询保护编辑。

**Tech Stack:** 现有 Python/sqlite3/FastAPI、JSON Schema 4.26.0、Electron/React/TypeScript。

**Spec:** T02 模块设计、跨模块约定；2026-09-16 用户明确选择空白/未完成草稿可落盘，采用/确认/生成时再校验完整性。

## Global Constraints

- HTTP JSON 1MiB、正文 100,000 Unicode 码点；不截断、不规范化换行。
- 身份和项目会话先校验；同 ID 重放查回执早于 CAS；不同内容复用 ID 拒绝。
- operation receipt、草稿、revision+1、savedAt 同事务；草稿不是采用，不修改下游。
- 只有已提交结果显示保存时间；失败/冲突/连接丢失均保留用户输入。
- 800ms 防抖；切换项目或关闭前 flush；未知结果查询原 ID，不自动换 ID 重写。
- 字符串自由文本可为空、内容字段可缺省；枚举/类型/ID/hash/限额仍有效。
