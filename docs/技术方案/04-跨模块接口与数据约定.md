# 跨模块接口与数据约定

设计基线 0.1.0，2026-09-15。适用于 T02–T14；T01 的运行时认证与控制协议保持不变。本文件细化工程契约，产品范围以 01–05 为准。

## 1. HTTP、桌面桥与权限

HTTP `/api/v1`，camelCase，UTF-8，拒绝额外字段、重复键、NaN、无穷和隐式类型转换。沿用 T01 Host/Origin/Bearer、统一错误与不暴露生产 docs 的规则。所有成功外层为 `{requestId,data}`。读取返回 DTO；写入返回 `MutationReceipt`：operationId、committedRevision、resourceId、state。202 表示本地任务已持久化，不能显示云端成功。

项目接口必须携带 `X-Project-Session`（每次打开产生的 UUID，运行时内存绑定项目及 read/write 模式）。会话失效返回 401 SESSION_EXPIRED；无写权限返回 403 PROJECT_READ_ONLY；对象不属项目返回 404 OBJECT_NOT_FOUND，不能通过 ID 跨项目读取。打开项目之前的 file-grants、projects 创建、project-sessions 和 settings 接口仅用运行时权限。

渲染层只调用固定桌面命令：chooseProjectDirectory、chooseImportFile、chooseExportTarget、createProject、openProject、getProject、saveDraft、previewAdoption、adoptRevision、confirmRevision、undoAdoption、planTask、startTask、getTask、recoverCall、editTimeline、runChecks、exportFilm、getCosts、setProviderCredential、createDiagnostic。每项 main 映射到固定 HTTP 操作并校验 sender/frame/origin/schema，不提供任意 HTTP 方法或 URL 参数。

文件选择由 main 返回一次性 grantId，不给 renderer 路径。main 经 `POST /file-grants` 向后端登记原生对话框选定的绝对路径、用途和窗口 ID；此内部接口不暴露给 renderer。grant 绑定窗口/会话、用途和五分钟 TTL，首次业务受理时消费，重试同 operationId 返回原回执而不再次消费。后端检查真实路径、目录属性及 junction/symlink，导出使用精确选定目标，禁止扩大为整盘权限。Key 只作为用户主动录入的秘密经固定入口送后端，永不通过读取 DTO 返回。

普通 JSON 请求上限 1MiB，故事正文最多 100,000 Unicode 码点；超限明确拒绝且不静默截断。供应商输入限制更小时在计划前提示，100,000 是编辑输入保护边界，不是模型支持承诺。单个列表默认 50、最大 200、opaque cursor；大正文/媒体不嵌入列表。导入文件大小和解码资源另在 T02/T09 校验。

T05 版本对照读取为明确例外：RevisionPage 包含正式 TypedPayload，canonical UTF-8 单版本最多 700 KiB，页内容预算最多 800 KiB，仍受最大 200 条和 UUID 游标约束，以保证业务桥响应小于 1 MiB。超大候选以 `REVISION_SIZE_LIMIT` 422 拒绝且不截断，草稿保存边界保持不变。

业务生成细分阶段 `PipelinePhase` 决定模型配置：改编、大纲、分场、台词、人物、场景、道具、关键帧、视频、配音、口型、音乐、音效、检查分别设置，同一细分阶段无单角色/镜头覆盖。`Stage` 仅作八类预算汇总：story_*→story，image_*→image，其余同名；后端校验 phase/stage/capability 的匹配，不能把故事四阶段强制合用一套配置。

## 2. 防重、并发与版本

写命令结构：`{clientOperationId,expectedRevision,payload}`。UUIDv4 全小写；requestId 只用于诊断。project.revision 是用户保存/采用/配置/计划启动等写命令的提交序号，每次成功事务递增 1；读操作和执行器进度不递增。后台进度使用 eventSequence 单独递增，不能不停制造草稿冲突。全局设置使用独立 settingsRevision，项目创建 expectedRevision=0。

同一作用域 operationId 第一次受理保存 canonical request hash 和结果；重复相同内容返回同一资源/回执（即使 expectedRevision 已旧），不得新增费用。相同 ID 不同内容返回 409 OPERATION_ID_REUSED。不同 ID 的旧版本返回 409 REVISION_CONFLICT，不覆盖用户输入。认证之后先查已有操作，再做 CAS、文件 grant 与状态校验。项目通过 `GET /projects/{projectId}/operations/{operationId}` 查询；全局创建/配置通过 `GET /operations/{operationId}` 查询。操作结果与业务写入同事务，执行状态由对应 job/task 查询。

正文 SHA-256 对提交的原始 UTF-8 字节计算，保留换行，不因同长度而复用。版本 payload 不可更新；artifact 当前采用/确认指针可通过事务切换。草稿有独立 draftId 与 baseRevisionId；保存草稿不传播依赖失效。采用时核验持有输入版本的活动任务，仅实际依赖交叉时阻止，不因无关任务拒绝编辑。

## 3. 数据所有权和关系模型

每项目一个数据库；projects 只一行。全局文件 grants、打开会话、活动执行槽放内存；最近项目、能力档案和设置版本放应用配置数据库，Key 单独 DPAPI 加密。重启丢失 grant/会话后重新打开，不把它们当项目内容恢复。

`project.sql` 是最终关系模型的可执行设计，用于约束验证；生产不得在 T02 提前安装全部业务表。迁移顺序：002 项目/媒体/draft/operations/jobs，003 阶段模型配置，004 预算/任务/calls/costs/uploads，005 artifacts/revisions/依赖/采用，007 镜头索引，009 时间线版本索引，012 check_runs/checks/rights/exports。应用库最小创建恢复记录在 T02 建立，凭据和能力在 T03 扩展；完整归属见[数据模型说明](./数据模型/README.md)。各模块新增外键可通过建新表和一致备份完成。

T05 实施补充：确认必须依赖实际 CheckReport，因此 005 提前建立 check_runs/checks 的最小结构及引用检查存储；012 在其基础上补齐检查处理、权利和导出。提前的本地结构检查不代表完整 T12 功能或质量验收。

JSON Schema 在 API、模型结果解析与数据库写入前由后端运行时校验。SQL 不尝试理解人物知情、剧情遗漏或口型；用例语义检查负责。JSON 文件是设计样例，不作为第二个可编辑业务数据库。

草稿与正式成果使用不同校验层：`DraftPayload` 允许缺省字段和空白自由文本，仍限制类型、枚举、大小、额外字段和内部身份；`TypedPayload` 保持正式成果完整约束。2026-09-16 用户确认允许空白/未完成草稿落盘，采用、确认与生成才执行完整性准入。

## 4. 任务、计划和恢复

所有收费分支只有 `planTask → startTask`。planTask 本地编译模板和已知能力，不调用 AI、不上传；自然语言理解、创作、AI 检查也是明确收费 step。TaskPlan 绑定对象、目标、输入版本/媒体哈希、能力/模板/价目版本、step 列表、候选数、生成和检查次数、外发类型、请求档位、总上限及十分钟有效期。过期重新本地计划；未变输入仍需显示当前价格。任务参数用已核准档案，用户不能直接输入任意供应商 URL。

每个 startTask 只针对一个对象、一个阶段；同对象生成与指定预检可以是同计划内 steps。receipt 的 taskId 从 resourceId 得到；假服务和真实服务有不同 executionMode，假服务不能写真实账目。运行时只有一个主动任务执行槽，数据库有一个 active=true 的用户任务；跨项目切换不释放正在执行的槽。确定失败、未知或部分完成停止后续 steps、释放主动槽并保留占用；新的任务必须经明确启动，界面持续显示旧未知任务。

调用 prepared 和 submitting 分开落盘。prepared 重启后待用户继续；submitting 无返回 ID/响应一律 unknown，不重新生成 POST。有远端 ID 则查询原任务；已有结果则仅下载。恢复接口的 action 只能 query/download/stop_waiting/cancel_remote，后者仅支持并实测取消的档案允许。HTTP POST 的恢复用例不得调用 submit。结果、费用和观察状态分开；停止等待不改变远端/结算事实。

本地 job（导入、预演、导出、诊断）与收费 task 分表，查询本地 job 不访问服务商。本地 jobs 最多一个重媒体作业，同时允许轻量草稿/状态读取；与云任务并行时仍遵守输入快照锁。关闭先持久化，可恢复本地作业重新检查输入/磁盘，不自动新增收费任务。

## 5. 费用、估算与结算

金额均为 CNY 整数微元：1 元=1,000,000 microCny。预算/已发生/占用非负，退款或调整通过更正后的非负结算及追加事件记载，不更新原事件。价格精度在调用上限计算时向上取整到微元；实际结算按供应商依据记载，不能因数据库精度凭空加收。

cost_entries.call_id 唯一：pending 只计 reserved；settled 只计 settled，不两者相加。计划未提交只在 remainingWork 估算，提交某 step 后从未提交预测移除并建立占用。项目预算、阶段分配和本任务授权上限三个余额每次发送前均检查；总分配不超项目预算、阶段缩减不低于已发生与占用。后台用量超估应记录实际事实并停止下次提交，不伪称可截断服务商账单。

未来完工预测 = 已结算 + 待结算占用 + 未提交制作 + 明确返工情景；同一 workItemId 不能重复出现在已提交和未提交。账单核对为带依据的 settlement 写命令，可追加更正，不能把失败自动结算为零。OSS/素材采购等外部成本使用独立 expenseId，避免伪造生成 call；同样区分 pending/settled/estimated。

## 6. 内容与语义依赖

Revision 的 kind 为 story/asset/shot/speech/subtitle/timeline/observation。story 包含来源范围、必留要求、分场/台词与改编决定；shot 必须引用 requirementIds，并有明确起点/必要事件/终点。人物左右用 subjectLeft/subjectRight，画面方向单独描述。人物身份是 asset，服装/伤势等持续状态带适用镜头范围，瞬时姿态留在 shot。

依赖边按语义：identityVisual、dialogueAudio、subtitleTiming、referenceInput、requirementCoverage、revealTiming、timelinePlacement、mix、export。编辑影响由旧新 payload 的变更路径映射到这些 scope；无法确定的自然语言语义变更不能假定无影响，应显示需核对。图像/文本变更未采用不产生失效。

确认需要对应版本的有效检查；选中、采用、确认三者分开。首次采用可携带 confirm=true，但必须同一事务核查实际 gate；不能因按钮名字绕过。撤销恢复最近采用前的确认基准及关联快照，不删除新 revisions、media、calls、costs。

## 7. 时间线与检查

时间均为整数毫秒，区间为半开 `[startMs,endMs)`；媒体实测时长独立保存。输出 fps 用分子/分母，支持 24/25/30。RenderPlan 量化边界采用最近帧、恰半向后，非负时 `floor(ms*n/(1000*d)+0.5)`；同一量化边界用于相邻片段，字幕亦按帧量化，音频采样按相同时间原点处理。量化后为零的必需片段拒绝。素材入出点以源时间计，转场占两个相邻片段已有区间，不能无声扩大成片时长。

时间线唯一语义模型包含 image/video/voice/music/sfx/subtitle 轨及 clips、transitions、keyframes；字幕文字/定时引用 subtitle revision。预览、预演、导出都编译同一快照，renderer 播放误差与 FFmpeg 输出仍需实测，不能由共享模型宣称天然一致。

每条 check 绑定对象/结果 revision、基准 revision、ruleVersion、方法、已观察范围、证据和问题。普通瑕疵 accept_deviation 保留问题事实；blocking/unknown_required 只能补证/修改后复检解除。模型疑似匹配不直接升级为确定侵权。没有依据的规则不可批量阻断全部作品；规则目录写清适用条件和复核出口。只检查当前采用链，废弃候选不误拦。

检查执行和问题分开：check_runs / CheckReport 保存每次检查的 pass/fail/unknown/not_applicable、版本、规则、观察范围和限制；checks / Issue 只保存发现的问题。零问题不等于已检查，confirmRevision.checkIds 引用有效 CheckReport，必须覆盖当前版本的必要规则；GET /check-reports/{checkId} 可复核。问题表为空而没有报告时仍是待检查。

## 8. 统一错误与前端恢复

| 错误 | HTTP | 用户处理 |
| --- | --- | --- |
| SESSION_EXPIRED / AUTH_INVALID | 401 | 重开项目/重连，不重新提交生成 |
| PROJECT_READ_ONLY / GRANT_REJECTED | 403 | 关闭占用写窗口/重新选文件 |
| OBJECT_NOT_FOUND | 404 | 刷新项目，保留输入 |
| REVISION_CONFLICT / OPERATION_ID_REUSED | 409 | 查询原操作或重新对比草稿，不能换 ID 自动提交 |
| INPUT_LOCKED / TASK_BUSY | 409 | 保留草稿，等待或处理原任务 |
| BUDGET_EXCEEDED / PLAN_STALE / CAPABILITY_MISSING | 409 | 调预算/重新计划/配置能力；均不自动调用 |
| MEDIA_MISSING / MEDIA_TOO_SHORT / CHECK_BLOCKED | 409 | 定位素材/预览时长调整/补证复检 |
| VALIDATION_FAILED / TIMING_OVERFLOW | 422 | 定位具体字段、镜头、时长差 |
| STORAGE_UNAVAILABLE | 503 | 处理磁盘/权限，原数据保留 |

错误字段沿用 code/message/affectedIds/recoverableAction，业务动作枚举扩展为 reopen_project、review_changes、configure、review_budget、locate_media、review_checks、query_operation 等；T01 错误不自动获得这些新动作。
