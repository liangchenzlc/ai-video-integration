# T10 动态视频、对白与传输

设计基线 0.1.0；待实现。前置 T04–T09。目标：在可核对的制作依据上逐镜生成动态视频，并保留可见对白、必要动作和原任务恢复链。

## 1. 正式与研究路径

正式制作需要全片预演确认；条件研究试片只要求本镜已采用文字、实际参考/关键帧、适用配音、局部预演、接口和预算。只准入当前一镜，不自动推进下一镜。研究结果未变基准且经过采用/确认可复用。

visible 对白必须使用真实支持的音频驱动或后置口型能力。VO/OS 单独合成声音；无兼容路径明确拒绝该付费步骤并提供配置/经采用改写，禁止藏嘴或自动改旁白。多人同时说话、大侧脸和遮挡按能力档案单独判断。

## 2. 接口与数据

`POST /video-readiness`：shotRevisionId/speechRevisionIds/capabilityId/path → ReadinessResult，纯本地核对已知条件。动态生成、口型处理分别复用 stage=video/lipsync 的 TaskPlan，仍只对应同一个当前镜头。每个阶段独立授权，不把后置口型当视频费用已包含。

复用 ShotPayload、SpeechPayload、Media、Task/Call/Upload、ObservationPayload。口型后置结果是新 media/revision，绑定原视频和配音哈希，保留原片。原片视频与声音轨分开选择采用，去重复人声；无法分离时给出实际处理选项。

## 3. 参数和上传

请求前比较叙事计划、供应商请求档位、返回实测、采用区间。例如计划3秒但模型5秒档，请求/估价5秒并告知拟用3秒。首帧、尾帧、多参考互斥规则来自精确型号；文字写终态不算尾帧控制。audio=false 不允许显示已应用配音。

上传只在授权后的 prepare_inputs 阶段进行。uploads 先登记目标对象和 task/media 引用，再上传并保存校验和；签名窗口覆盖处理上限。运行/unknown 不删输入，失败或重启仍可定位；cleanup 只处理无活跃引用且超过披露保留期的对象。删除失败保留 delete_pending，不自动重生成。

## 4. 观察与采用

用户连续播放原片和相邻镜头，标记 observed/usable/problem 区间；抽帧只代表所查点，未覆盖处不标通过。裁片必须保留承载的动作/台词/反应，不能裁掉松手来掩盖错误。补拍 use=supplement 新 ShotId，替代 use=alternate 展示原镜全部要求是否覆盖。

下载/采用仍走 T02/T05，返回漂亮视频不自动切换当前片。上游采用改变时对应视频待更新，原任务费用和原片保留。

## 5. 验证

批次：ready 检查 → 假视频服务/上传恢复 → 真型号适配 → 原片观察/局部替换 → 人工效果准入。

| 示例 | 输入/故障 | 预期 |
| --- | --- | --- |
| V10-01 | visible 对白、无音频驱动/口型能力 | ready=false、零收费提交 |
| V10-02 | 配音输入存在但 audio=false | 参数冲突，不能忽略 |
| V10-03 | 签名到期不足、上传仍被 unknown 任务引用 | 不提交新生成、不清理对象 |
| V10-04 | task_id 成功后下载失败 | 原 ID 查询/下载，不二次 submit |
| V10-05 | R02 有落座无松手 | 必留过程失败；剪掉末段也不能通过 |
| V10-06 | 试片通过后输入哈希没变 | 可复用已采用结果，不强制重新购买 |

只有模型原片及真实听审/看片才能证明效果；Schema/假服务通过只说明设计及软件行为。
