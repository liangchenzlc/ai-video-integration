# T04 任务、费用与恢复

设计基线 0.1.0；待实现。前置 T02/T03。目标：每次提交的输入和最高费用明确，重复点击、断网和重启不导致自动再次生成。

## 1. 用户流程

选择当前对象及意图 → 本地生成计划 → 展示真实输入/外发、候选、生成/预检次数、费用和完工影响 → 用户启动 → 显示原任务进度/结果。候选默认 1。只允许一个主动用户任务，其他工作区可浏览或编辑无关草稿。

未知结果显示请求时间、服务商和可核对摘要，并明确可能已计费；提供查询原任务/打开说明，不出现自动重试生成。下载失败提供原下载恢复。停止等待只修改本地观察标志。

## 2. 接口

项目内 `POST /task-plans` PlanTask → receipt(planId)，`GET /task-plans/{id}` → TaskPlan；`POST /tasks` StartTask → 202 receipt(taskId)；`GET /tasks/{id}`、`GET /calls/{id}`；`POST /calls/{id}/recovery`；`POST /tasks/{id}/continue` 仅明确恢复未提交 steps。

`PUT /budget` SetBudget；`GET /cost-summary`、`GET /cost-entries`；`POST /calls/{id}/settlements` 带金额与依据；`PUT /external-expenses/{id}` 带独立采购/存储记录。准确结构见 [OpenAPI](../契约/business.openapi.json)，所有写入遵守操作防重及 CAS。

TaskPlan 是已持久化本地计划，不占用实际消费；startTask 校验 plan 不过期、内容/价目/能力未变、disclosureAccepted=true、authorizedMaximum 与计划最大值一致。多给授权也不能增 steps；少给则拒绝并要求重新计划。

## 3. 数据与事务

迁移 004：stage_budgets、task_plans、planned_steps、user_tasks、service_calls、call_events、cost_entries、external_expenses、uploads。stage_models 在 T03 已建立，不依赖尚未出现的预算表。T05 再加 task_inputs 到 revisions 的外键；之前计划存独立快照和哈希。

启动事务保存 user_task、授权和第一步 prepared call 及占用；调用前第二事务改 submitting；网络响应后立即落盘远端 ID/同步结果，再下载和登记。每个 step 候选以 ordinal 唯一标识，不因重复回调多记候选。生成客户端、SDK 和 HTTP 代理都必须关闭透明 POST 重试。

单任务唯一约束在项目库；跨项目的运行时 active slot 由唯一后端执行器管理。切项目后任务继续、顶部保留来源。结果未知/确定失败释放主动槽且停止后续调用，但旧占用保留；新任务仍须用户重新启动。重启扫描所有本次打开/待恢复项目，不自动发送 prepared 或 submitting。

## 4. 费用例子

项目预算 10,000,000 微元，video 分配 3,000,000；本次 4 秒单镜最大 1,200,000。提交后 settled=0、reserved=1,200,000，remainingWork 移除该工作项；结算 1,100,000 后 settled=1,100,000、reserved=0。重复结算不再加 1,100,000。未知时继续占用 1,200,000；内容撤销不减消费。

三重上限分别比较项目已发生+占用、阶段已发生+占用、同任务已发生+占用。候选/检查 step 估算总和必须不超 TaskPlan maximum，每个收费 step 调用上限明确。预算不足允许查询原任务/下载；查询若另收费必须已披露且保留对应恢复费用上限，不把查询当无限免费。

## 5. 状态与故障

prepared→submitting→running→pending_download→succeeded。同步结果可由 submitting 直接 pending_download。submitting 响应丢失→result_unknown；running 查询失败保持远端未知，不重发。确定失败→failed，部分成果保留。取消仅已验证服务商成功取消后 call=cancelled，结算独立。

费用更正追加 call_event，cost_entries 当前值更新；原事实不能删除。没有价格使用明确标估算的保守上限，未填则拒绝，禁止零价兜底。synthetic 使用独立夹具项目与假服务，UI 和数据 provenance 必须区分。

## 6. 验证与交付

批次：计划/预算计算 → 持久化执行器与防重 → 假服务故障注入 → 前端未知/下载恢复 → 账目更正与完工预测。

| 示例 | 故障窗口/输入 | 断言 |
| --- | --- | --- |
| V04-01 | 同 operationId 双击 start | user_task 和生成提交各一次 |
| V04-02 | 供应商受理后 ID 返回前断网 | submitting→unknown；后端重启 submit 次数仍为 1 |
| V04-03 | ID 已落盘后退出 | 只 query 原 ID，成功后 download |
| V04-04 | 三候选，第 2 个失败 | 第 1 个保留，第 3 个未提交，不计第 3 个费用 |
| V04-05 | 结算重复、撤销采用 | charged_costs 始终只一条，费用不随撤销减少 |
| V04-06 | remaining 包含已提交工作项 | 校验拒绝重复预测；不以预算增加触发调用 |

必须用计数假服务与真实崩溃窗口测试，纯 Schema 通过不证明防重实现。交给 T05 稳定任务输入锁与 append-only 账目。
