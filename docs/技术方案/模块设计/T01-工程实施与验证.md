# T01 工程实施与验证

版本：0.6，2026-09-16。A–E 工程批次已完成，见[T01 最终验证](../../开发记录/T01-最终验证与Review.md)与[详细交接](../../开发记录/T01完成后的开发交接.md)。T02–T14 尚未实现。

**目标：** 交付可重复构建、受认证连接、正确退出的 Windows 桌面与本机 FastAPI 最小模块。

**架构：** Electron 管理一个 Python 监督进程，监督进程持有 Job Object 并管理一个 API 进程及其媒体子进程。业务仅在 API 进程；前端通过有限桌面桥和 HTTP 契约访问。

**技术栈：** Electron、React、TypeScript、FastAPI、Python、Uvicorn、Pydantic、pywin32、PyInstaller、electron-builder。

**设计依据：** [T01 主设计](./T01-桌面启动安全和导航.md)、[接口与启动协议](./T01-接口与启动协议.md)。

前端监督器约定：`start(): Promise<RuntimeSnapshot>`、`restart(expectedGeneration: number): Promise<RuntimeSnapshot>`、`stop(reason: 'app_exit' | 'user_restart'): Promise<void>`、`snapshot(): RuntimeSnapshot`、`subscribe(listener): unsubscribe`。start/restart 在对应操作状态提交后返回受理快照，ready 或后续失败由事件通知；stop 必须在清理确认后完成或返回 STOP_TIMEOUT。

Python 核心约定：`create_app(context: RuntimeContext) -> FastAPI`、`run_supervisor() -> int`、`run_api() -> int`。Windows 适配器提供 `spawn_suspended_in_job(argv) -> ManagedProcess`、`terminate_job(exit_code)`、`wait_empty(timeout_ms) -> bool`、`close()`；ManagedProcess 保存真实进程句柄，公开的 PID 仅用于核对和诊断。

RuntimeContext 字段为 runtimeId、generation、tokenBytes、appDataDir、mode、apiVersion、controlVersion、backendVersion、startedMonotonic、ready。秘密字段禁用 repr/序列化；HTTP 模型从中选择白名单字段，不直接 dump context。

API 启动采用 `uvicorn.Server(config).serve(sockets=[boundSocket])`，配置固定单 worker、reload=false、loop=asyncio、http=h11、ws=none、lifespan=on、proxy_headers=false、access_log=false、timeout_graceful_shutdown=4。日志使用显式 stderr 配置，不能使用会向 stdout 写访问日志的默认配置。API 观察 server.started 后才将 context.ready 置为 true 并发送管道 ready；main 仍需完成认证健康检查。API 控制管道在独立线程读取，停止命令通过事件循环的线程安全入口先置 ready=false 再请求服务器退出；不从读取线程直接关闭事件循环。

## 3. 开发启动与构建

首次准备时按精确候选依赖创建 package.json/pyproject.toml，然后生成两份 lockfile；后续一律 frozen 安装。以下为标准工具命令示例；本机优先使用 scripts 中已接入固定工具路径的入口：

```powershell
uv python install 3.13.15
uv lock --project backend
uv sync --project backend --frozen
pnpm --dir frontend install
```

首次 lock 生成并检查依赖后，重复安装使用 `pnpm --dir frontend install --frozen-lockfile`。Node/pnpm/uv 版本在脚本启动时检查，不满足就给出准确要求，不默默使用用户 PATH 中其他版本。

开发入口为 `scripts/dev.ps1`，统一检查/打包/目录包验收入口为 `scripts/check.ps1`、`scripts/pack-win.ps1`、`scripts/test-packaged.ps1`。脚本兼容 Windows PowerShell 5.1，不修改机器执行策略。开发时使用项目 `.venv` 对应的实际 CPython 可执行文件，参数为 `-u -X utf8 -m app.entrypoint --role=supervisor`，工作目录固定 backend；从受控配置计算 `__PYVENV_LAUNCHER__=backend/.venv/Scripts/python.exe` 以加载项目依赖。监督器同样通过 `python_launch.py` 启动 API。Windows venv 的 python.exe 是重定向启动器，直接启动会造成 CreateProcess PID 与运行 Python 的 PID 不一致；T01-A 已实测并修正。生产仍直接启动自带的 onedir exe。不在 Electron 中执行 `uv run` 或另开可见终端。

前端单独组件开发使用同一 BridgeResult 的测试替身。后端 API 单独测试通过 ASGI 客户端和构造的测试 RuntimeContext；真实桌面联调必须通过监督器，不能把没有认证的 Uvicorn 裸服务当正式开发模式。

| 前端脚本 | 实际命令或职责 |
| --- | --- |
| dev | electron-vite dev |
| typecheck | tsc --noEmit，分别覆盖 main/preload/renderer 配置 |
| lint | eslint . 与 prettier --check . |
| test | vitest run |
| build | electron-vite build |
| test:e2e | playwright test |
| pack:win | electron-builder --dir --win --x64 |
| api:generate | openapi-typescript ../contracts/openapi.json -o src/api/runtime-types.ts |

后端检查命令为 `uv run --project backend ruff check backend`、`uv run --project backend mypy backend/app`、`uv run --project backend pytest backend/tests`。根脚本逐项检查退出码，失败立即停止；不依靠 PowerShell 默认继续执行而报告成功。

契约导出入口为 `uv run --project backend python backend/scripts/export_openapi.py --output contracts/openapi.json`。先导出、与设计契约核对，再生成 TS；类型检查与契约检查都通过才允许合并该批次。

## 4. 生产目录与 Python 打包

```text
release/t01/win-unpacked/
  AI Video Integration.exe
  resources/
    app.asar
    backend/
      avi_backend.exe
      _internal/
```

PyInstaller 使用 onedir、`console=True`，而不是 windowed/noconsole。官方文档明确无控制台构建可能令 stdin/stdout/stderr 为 None，会破坏本方案管道。窗口不可见由 Electron 的 `windowsHide:true` 和 Windows 子进程 `CREATE_NO_WINDOW` 实现。

生产 main 从 `process.resourcesPath/backend/avi_backend.exe` 启动 supervisor；supervisor 使用同一 exe 的 api role。入口调用必要的冻结运行时初始化，role 路由先于 API 启动；所有模块 import 不绑定端口、不读取 Key、不创建数据库。

后端构建命令约定：`uv run --project backend pyinstaller --noconfirm --distpath backend/dist --workpath backend/build backend/avi_backend.spec`。桌面 extraResources 把 `backend/dist/avi_backend/` 整个目录复制到 resources/backend，不能只复制 exe。T01 不收集研究素材、`.local`、凭据、Python 虚拟环境或用户项目。

前端生产使用固定 `app://ui/` 来源载入打包资源，协议只提供白名单静态资源，不访问项目文件。开发来源固定 `http://127.0.0.1:5173`、严格端口占用检查；开发 HMR 例外只在开发 CSP 中启用。`app-media://` 在 T02 才实现，本模块不暴露任意文件协议。

子进程环境采用白名单：SystemRoot、WINDIR、TEMP、TMP、USERPROFILE、LOCALAPPDATA、APPDATA 和必要的受控 PATH；设置 PYTHONUTF8=1，移除 PYTHONPATH/PYTHONHOME、NODE_OPTIONS 及服务商密钥环境项。开发解释器、打包 exe 和配置目录均由 main 计算，不能由 renderer 改写。

应用配置根使用 Electron userData 路径，经 init 交给后端；T01 只允许脱敏运行日志，不创建业务配置/数据库。所有 UTF-8 文件显式编码，避免依赖 Windows PowerShell 的默认 ASCII 管道或系统代码页。
