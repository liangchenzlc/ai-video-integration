# T12 检查、修订与正式导出

设计基线 0.1.0；离线工程已实现，基础验证与外部验收边界见[本轮记录](../../开发记录/2026-09-16-T08-T13实现与验证.md)。前置 T05/T09–T11。目标：问题有位置和依据，导出来自用户确认的同一版本，失败不丢项目和原件。

## 1. 需求与交互

检查页按对象/时间定位问题，显示依据、观察范围、严重性、处理入口和限制。普通偏差可以记录原因接受；必要风险未知只能补证或复检。问题数量不能代替严重性，也不因为无关废弃候选有问题阻止导出。

导出前展示采用版本、目标画幅/分辨率/fps、字幕开关、预计空间和未解决阻断。目标通过原生保存对话框选择；覆盖现有文件必须明确确认。导出进度是本地 job，取消不取消云端生成、不删原媒体。

## 2. 初始规则目录

| ruleId / v1 | 条件与依据 | 结果与恢复 |
| --- | --- | --- |
| media.available | 当前采用引用 missing/quarantined 或无法完整解码 | blocking；重新定位同哈希或采用替代 |
| timeline.bounds | 时间越界、零长、无意黑洞或非法转场 | blocking；修剪辑并本地复检 |
| reference.ready | 正在计划的必要参考未核对/不兼容 | 阻止相关生成；导入/核对/改方案 |
| requirement.coverage | 必留未承载或事件可能被裁去 | 明确未承载为 blocking；语义不确定为 unknown_required，内容审核解决 |
| dialogue.timing | 已实测声音超容量、字幕越界或明显遗漏 | blocking；修时长/字幕/采用内容后复检 |
| identity.continuity | 身份/道具/空间变化违背已确认基准 | 人工或 AI 附位置证据，必要项待核对；普通偏差可接受 |
| rights.source | 当前使用素材需来源/授权而缺证据 | unknown_required；补来源和适用说明后核对，不以 AI 猜测认定侵权 |
| audio.delivery | 缺必要声音、重复人声、明显失真 | 检测+试听；修混音或素材 |

平台规则只在用户选用且有确切来源/版本/日期时增加，默认通用 MP4 不假定某平台强制规范。涉及生成内容标识等发布要求由发行前的适用规则审查落实，不能在无依据时伪造法定结论。没有适用条件的 unknown 不批量阻断所有项目。

## 3. 接口与数据

`POST /local-checks` RunLocalChecks → 202 local job，仅确定的本地检查；AI 语义/视觉检查用 stage=check 的有界收费任务。`GET /issues` 分页；`POST /issues/{id}/decisions` 仅 accept_deviation/request_recheck/attach_evidence，用户不能直接写 resolved。

CheckReport/check_runs 保存实际检查执行及 pass/fail/unknown/not_applicable，即使没有问题也要保存报告。`GET /check-reports/{checkId}` 返回报告；local job.resultId 指向报告。Issue 存 artifact/revision/baseline/rule/version/method/severity/status/evidence/time/limitations；checks/check_decisions 保存问题及决策历史，并关联 check_run_id。确认使用有效报告的 ID，不以问题列表为空代替通过。新结果不继承旧合格结论；补证不自动解决问题，核对后由检查用例建立新证据/结论。

`POST /exports` ExportFilm → 202 receipt(exportId)，`GET /exports/{id}` 获取 ExportRecord.jobId 后查 local job。输入 timelineRevisionId、targetGrantId、burnSubtitles、overwriteConfirmed。timeline 内容与导出开关共同冻结并计算 inputHash；字幕关闭后仍检查剧情画内文字。

## 4. 导出事务与恢复

在同一事务保存 export 记录、local job、采用媒体/检查快照和 operation；编码时不持 SQLite 事务。生成 RenderPlan → 临时目标文件 → 完整解码/尺寸/fps/时长/音轨核对 → 同盘原子替换已授权目标 → 登记可用导出媒体与完成状态。发布文件成功而登记前崩溃时按 manifest/hash 补登记，不能重新购买素材。

若用户目标在项目目录外，项目 exports/ 中保留规范成片及 manifest，media_files 仍使用项目相对路径；再流式复制到目标目录的临时文件、核对哈希并原子发布。外部目标交付失败记本地 job 失败/可重新交付，内部成片仍保留，不能宣称目标已成功。不得把外部绝对路径写进 media_files.relative_path 或渲染层 DTO。

编码期间可保存无关草稿；新的采用版本不改变本次输出，完成页明确版本不同。覆盖之前保留旧目标到成功发布时；失败/取消清理本次临时编码文件前确认路径和归属，唯一生成原件不自动删除。

## 5. 验证与交付

批次：规则与位置 → 版本检查/补证/接受 → 冻结导出 → 编码核对 → 故障恢复。

| 示例 | 输入/故障 | 预期 |
| --- | --- | --- |
| V12-01 | blocking 问题请求 accept_deviation | 409 CHECK_BLOCKED；问题事实不变 |
| V12-02 | 废弃候选缺媒体、当前采用完整 | 不误拦当前导出 |
| V12-03 | 导出中磁盘不足 | failed、原项目/素材/旧成片保留 |
| V12-04 | 导出中采用新 timeline | 本次完成标旧快照版本，不冒称当前输出 |
| V12-05 | burnSubtitles=false | 关闭后期字幕，不隐藏画内必留文字检查 |
| V12-06 | 请求两次同 export operationId | 同 export/job，不重复编码覆盖 |

正式交付应在干净机器完整解码并和预览抽样对比；技术可播放不能代替艺术验收。
