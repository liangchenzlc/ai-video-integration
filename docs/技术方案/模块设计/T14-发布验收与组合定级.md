# T14 发布验收与组合定级

设计基线 0.1.0；待执行。前置应用 T01–T13 和真实模型能力证据。此模块是评测工作流，不增加产品后台管理页面或收费 API。

## 1. 样本与通过条件

沿用 05/06：B01–B06 六个独立项目，两故事、三种输入、至少两题材、横竖屏；单条 28–32 秒、6–8 镜、1–2 主要角色，同一人至少跨3镜，简单连续动作、可见中文对白、正式配音/字幕/音乐/必要音效。保留第一次结果和全部失败/未采用，不把同片改名算独立样本。

质量：技术、一致性、艺术和声音分别通过，无严重缺陷；嘴部/字幕起止目标≤200ms，同时实际看片听审。最终至少一套完整组合适配实际写实目标；二维研究片只验证流程。AI 音乐音效或正式传输等首版必要分支未通过，完整首版仍不通过。

## 2. 评测资料与数据

离线 AcceptanceRecord Schema 定义 sampleId/reviewerId/evidenceMediaIds/四类结论/notes/provenance；human 与 synthetic 分开，synthetic 永远不能计入发布统计。每个项目关联完整调用明细和 costs，导出版本/哈希固定。来源与档案保存在受控评测目录，不随普通安装包分发研究素材。

两名真实独立评审先各自记录，再对争议按时间位置复看；不能一个 AI 扮两人。用户主观接受不自动等于独立评审通过。

## 3. 新手脚本

招募五名此前无 AI 工具经验的中文 Windows 用户，告知使用其账户/测试额度的明确范围。要求独立完成配置、建立项目、选择/采用、一次局部修改、费用理解、模拟恢复入口与导出。工作人员只记录求助点，不代操作；至少四名完成。记录任务成功、错误、求助、人工耗时、等待、放弃原因和对费用/版本的解释。

不得为证明自主完成隐藏配置复杂度。G00 原型测试只验证理解，不替代真实服务、费用与故障恢复试用。

## 4. 同质量配对成本

应用与手工多工具流程用对称参考、可比模型及同一必留要求，交替先后。每条记录人工有效时间、模型等待、总时间、调用/采用率、返工、预检、音频处理及外部存储费用，现金账单和无赠额参考分开。

发布条件仍为人工时间中位数、总模型费用中位数低于对照，一致性返工中位数不高于对照，同一质量门槛通过。只有六条项目并不自动满足配对，应为各自准备可比较手工过程；未知结算不能当零。报告实际比例而非预设营销数字。

## 5. 验证例子与结论规则

| 示例 | 输入 | 预期 |
| --- | --- | --- |
| V14-01 | 五人里3人独立完成 | 新手门槛失败，不能四舍五入通过 |
| V14-02 | 六片共用同一成片文件改名 | 样本独立性失败 |
| V14-03 | 艺术高分但持续口型错位 | 声音/对白质量失败，不用平均分覆盖 |
| V14-04 | 单个成功镜头费用更低 | 不推断完整项目降本 |
| V14-05 | 评审 provenance=synthetic | 只用于格式验证，不计入真人人数 |

最终组合档案列准确版本/地域、验证日期、支持风格/时长/动作范围、已知限制、样片和账单依据。变化影响关键能力时降级为待复验，不沿用旧组合的宣传结论。
