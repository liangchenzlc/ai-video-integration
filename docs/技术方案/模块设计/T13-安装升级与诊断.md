# T13 安装、升级与诊断

设计基线 0.1.0；离线工程已实现，基础验证与外部验收边界见[本轮记录](../../开发记录/2026-09-16-T08-T13实现与验证.md)。前置 T01–T12。目标：无预装 Python 的 Windows 11 x64 用户能够安装、配置、恢复和升级，诊断不泄露创作正文或凭据。

## 1. 需求与发行边界

内部先交付 win-unpacked 目录包；对外安装包沿用 electron-builder NSIS，Python onedir 位于 asar 外。程序资源只读，项目/应用配置写用户选择位置。FFmpeg 初始由用户选择兼容本机构建；缺工具时提供准确配置说明，不把研究二进制直接随包分发。

首版采用用户主动下载安装更新，不新增自动更新服务器。安装器检测旧实例并请求正常关闭，不能按 python/ffmpeg 进程名杀进程。卸载只删除应用资源，项目和用户配置默认保留，任何清理需明确列出范围。

## 2. 接口与模型

运行状态继续 T01；项目迁移 T02；`POST /diagnostics` CreateDiagnostic → 202 global job，含 includeProject/includeContent/targetGrantId。先本地显示要包含的文件种类和敏感范围，用户选择保存到授权位置；生成文件不自动外发。

默认 includeContent=false，只含版本、错误码、耗时、状态摘要，排除秘密/签名 URL/原文/声音。即使 includeContent=true，也不得包含凭据和令牌。诊断文件清单必须可预览，保存后用户自行决定分享。

发行 manifest 包含 app/backend/API/control/schema 版本、依赖锁摘要、文件哈希、构建环境、签名信息与许可证清单。它是构建产物，当前文档不伪造实测值。应用层 jobs/global_operations 使用应用库；不新增远程账户、许可证服务器或遥测。

## 3. 升级与回退

应用替换前保留可回退程序；项目打开时检查 schema 兼容，迁移前 backup API 产生一致副本并验证；迁移失败保留原库和副本，不能以新空库覆盖。旧程序拒绝写新 schema；用户只能明确恢复备份到新目录或重装兼容版本，不能直接降低版本号继续写。

记录 lockfile 冻结安装、后端运行时/SQLite 与 Windows 实际版本、启动时间/内存/体积、中文/空格路径、普通权限运行。设备最低配置由测量确定；1280×800 是交互验证尺寸，不作 CPU/RAM 要求。
