# T05 版本、采用、依赖与撤销

设计基线 0.1.0；待实现。前置 T04。目标：用户能看清“正在看哪版、当前片用了哪版、哪版已确认”，局部修改只影响相关成果，撤销不会抹掉消费。

## 1. 交互与接口

浏览候选仅选中；编辑保存 draft；`POST /artifacts/{id}/revisions` 从 draft 创建不可变候选，首次创建同时登记 artifact。`GET /artifacts/{id}/revisions` 分页返回历史候选。`POST /artifacts/{id}/adoption-preview` 只计算影响，返回 Impact，不修改基准、不调用模型。

`GET /artifacts/{id}` 返回安全状态 `{id,kind,adoptedRevisionId,confirmedRevisionId,needsUpdate,latestAdoptionId}`，不得根据候选列表顺序猜测当前版本。latestAdoptionId 为全项目最新未撤销采用且属于该对象时的 ID，否则为 null；使重开后仍可发起撤销，实际执行仍核验关联冲突。当前已确认要求 adopted 与 confirmed 相同且 needsUpdate 为 false。正式候选的 canonical UTF-8 payload 最大 700 KiB，超限返回 `REVISION_SIZE_LIMIT` 422，保留草稿；版本列表同时遵守最大 200 条和 800 KiB 内容预算，通过 UUID 游标继续取页。

采用使用 `POST /artifacts/{id}/adoptions`，必须提交 previewId/toRevisionId/confirm。预览保存在短时内存，绑定当前项目 revision、对象、候选及输入哈希，五分钟失效；重启重新预览。`POST /artifacts/{id}/confirmations` 指定 revisionId/checkIds，`POST /adoptions/{id}/undo` 恢复最近可撤销采用。原操作查询遵守 T02。

界面并排旧/新、保持项、受影响对象、必要复检和成本未知项。用户放弃不改变已采用链；能合并采用并确认时给一个主动作，必要检查不满足则只能采用并标待审核。

确认依赖显式报告。为支持本模块，提前实现 T12 的 `POST /local-checks` 和 `GET /check-reports/{id}` 最小结构检查：只支持 `structural` 与 `references`，规则版本为 `local-structure-v1`。请求的 revisionIds、ruleIds 都必须非空；返回 accepted MutationReceipt，随后通过既有 job.resultId 读取 CheckReport。报告仅证明结构及引用完整性，不能代表叙事、视听质量、权利或人工审核通过。

## 2. 数据模型

迁移 005 引入 artifacts、revisions、revision_media、dependencies、adoptions、task_inputs。Draft 的 artifactId 在正式 revision 创建时校验/登记；kind 创建后固定。revisions 的 parent 与采用/确认指针均要求同 artifact；SQL 复合外键防串对象。payload 用 TypedPayload，引用媒体另写 revision_media 便于缺失定位。

revision.content_hash 对规范序列化 payload 计算；sourceHash 对原文本字节计算，两者用途不同。已存 revision 不能 UPDATE/DELETE。选中是 UI 状态，不存 adopted。当前确认可仍指旧版，但 adopted 与 confirmed 不同时不能显示当前已确认。

## 3. 事务与依赖传播

采用事务：CAS → 校验 preview/候选及活动输入锁 → 记录采用前当前与确认指针/下游标志/承载与时间线关系 → 切 adopted → 根据变更 semantic_scope 标实际下游 needs_update → 可用时确认 → 保存 operation receipt。整个过程不等待云端或用户。

依赖方向 from=上游，to=下游。禁止形成环；采用前 DFS/拓扑检查，并且快照使用版本 ID。身份颜色→identityVisual；台词→dialogueAudio/subtitleTiming；字幕独立改字→export；重排→revealTiming/timelinePlacement；音乐→mix/export。未确定语义保留需核对，不能为了少返工漏掉义务。

撤销只支持最近可恢复采用，若之后另有会改变同关联的编辑，则先预览冲突，不整库回退。恢复采用前已确认基准与关联；新版本、媒体、调用、占用均保留。无已确认基准时恢复原采用/未确认状态，不虚造确认。

## 4. 验证

批次：不可变版本/CAS → 影响预览与事务 → 语义传播 → 最近采用恢复 → 前端三种状态对照。

| 示例 | 变更 | 预期 |
| --- | --- | --- |
| V05-01 | 未采用外套改色 | 当前镜头/配音/确认均不变 |
| V05-02 | 采用外套改色 | 仅引用角色视觉与检查失效，无关配音不失效 |
| V05-03 | 只改单句字幕标点 | 字幕及导出待更新，音频调用数不变 |
| V05-04 | 活动任务锁住角色 r1；采用 r2 | INPUT_LOCKED，草稿仍可保存；无关角色可采用 |
| V05-05 | 给 A 采用 B 的 revision | 外键/用例拒绝；指针保持原状 |
| V05-06 | 采用后撤销 | 基准/关系恢复；所有费用/原片保留 |

交付依据需包含依赖图和事务中断前后快照。下一模块接收稳定候选、真实输入快照、采用和复检用例。
