# 模块设计模板

模板版本：0.3，2026-09-15。供模块设计迭代使用，模板本身不是完成证据。T01–T14 已有设计基线，见[模块导航](../README.md)；后续直接维护对应模块文件，不重复复制一份设计。

## 1. 基本信息与范围

写明模块编号、版本、状态、对应原开发任务、前置模块及证据。用一句话描述用户可以完成的动作，列出本模块实现内容和后续归属，明确本地能力、假服务和真实模型能力的界线。

## 2. 用户流程与交付

说明入口、正常路径、修改路径、失败和恢复出口；提供可演示结果。描述加载、空态、保存/提交中、冲突、断开和恢复状态，不能只设计正常成功页面。

## 3. 前端设计

列出新增或修改的工作台、关键组件、临时视图状态和桌面桥。业务数据由哪个 API 提供、草稿何时保存、操作响应丢失后如何查询，都需有明确处理。

## 4. API 契约

为实际所需接口写明方法、路径、请求/响应字段、枚举/大小边界、认证与项目归属、版本条件、状态码、分页和防重机制。标注 OpenAPI 与前端类型变更；接口示例不携带真实凭据或签名地址。

## 5. 后端用例与领域规则

说明每个用例的输入、输出、对象所有权、状态转换、允许/拒绝条件和依赖方向。长任务如何提交、查询、停止与恢复，是否可能收费或外发，要分别写清。

## 6. 数据与文件

列出本模块实际需要的表/字段、主外键、唯一约束、索引、事务边界和迁移版本。说明 expectedRevision 冲突、并发写入、备份、崩溃窗口和媒体完整性；不需要持久化时明确原因。

## 7. 安全、授权与成本

说明文件授权、路径范围、网络目标、敏感字段、日志脱敏和权限检查。涉及模型时列出输入快照、调用数量、能力/价格依据、预算、失败费用和用户授权范围。纯本地操作明确无生成调用。

## 8. 实现批次

按最小可运行闭环分批，逐批给出前后端改动、可检查产物和出口条件。避免把未来模块作为“顺便完成”的内容；必要接口替身需标明假服务。

## 9. 验证与验收

为每个关键正常/失败/恢复场景给出输入、步骤、预期、证据和对应原验收项。区分单元、API/数据库、桌面 E2E、真实能力测试和人工评审；不适用项说明依据，不能用删除验收项掩盖能力缺失。

## 10. 交付记录与下一模块输入

实施后记录准确版本、实际命令与结果、产物位置、设计变更和已知限制，回写原开发计划已通过的复选框。写明给下一模块的接口/数据/夹具；阻塞事项写清验证动作和负责模块，不能以“以后再说”标记完成。
