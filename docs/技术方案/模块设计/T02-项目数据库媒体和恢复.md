# T02 项目数据库、媒体和恢复

设计基线 0.1.0；待实现。前置 T01 通过。目标：用户可以创建、保存、重开项目，导入与重新定位媒体，遇到中断不会丢掉唯一原件。

## 1. 需求与交互

首页新建/打开/最近项目；新建输入名称、画幅、输出档位、帧率、目标时长。目录必须通过原生对话框选择；非空且不是本产品项目的目录不得覆盖。缺模型仍可创建本地草稿。最近项目记录失效时提供重新选择入口。

编辑后防抖 800ms 保存；切换对象或关闭前主动 flush。保存中显示状态，只在提交成功显示保存时间。失败保留输入并可重试同一 operationId；CAS 冲突展示已保存和当前输入两份文本，不做隐式覆盖。第二窗口可只读，数据库迁移、导入和费用写入均禁用。

## 2. 接口与示例

接口字段以 [business.openapi.json](../契约/business.openapi.json) 为准；示例通过 operationId 在 [business.examples.json](../契约/business.examples.json) 查找。

| 操作 | 接口 | 请求 → 结果 |
| --- | --- | --- |
| 文件授权 | POST /file-grants | main 登记 grant/path/purpose/windowId；renderer 不可调用 |
| 创建 | POST /projects | CreateProject → 201 MutationReceipt，resourceId=projectId |
| 打开 | POST /project-sessions | grant + requestedMode → Session，返回 read/write 实际模式 |
| 查询/保存 | GET /projects/{id}；PUT/GET /drafts/{draftId} | Project、SaveDraft、Draft；保存不采用 |
| 导入 | POST /imports | ImportMedia → 202，resourceId=jobId |
| 媒体 | GET /media/{id}/metadata；GET /media/{id} | metadata；有界二进制 Range |
| 重新定位 | POST /media/{id}/relocate | fileGrant + expectedHash；保持原 mediaId |
| 作业与恢复 | GET /jobs/{id}；POST /jobs/{id}/cancel；GET /operations/{id} | 查询原作业/原提交，不新建导入 |

除全局入口外前缀 `/api/v1/projects/{projectId}`。校验路径 ID 与 body 中 draftId 一致；新 draft 的 artifactId 是预分配 UUID，T05 才登记正式 artifact，T02 不伪造采用版本。

## 3. 数据和事务

迁移 002 建 projects、operations、drafts、media_files、import_intents、local_jobs。字段/约束见 [project.sql](../数据模型/project.sql)；应用库见 [application.sql](../数据模型/application.sql)。正文保存完整 UTF-8，源范围使用 Unicode 码点偏移。

创建涉及应用库与项目库，不能声称跨库原子事务：先在应用 global_operations 写 prepared 和预分配 projectId/目标；在授权目录建立标记与 staging 项目；创建完整项目库并关闭/刷盘后原子发布；最后应用操作改 committed。崩溃扫描该操作和 marker，只认匹配 projectId/operationId 的目录；不可判定时保留文件并提示，绝不覆盖其他目录。重复创建查询原操作。

每个连接 foreign_keys=ON、WAL、FULL、busy_timeout=3000ms；应用内互斥，项目 OS 写锁。网络/同步冲突目录拒绝直接写入；先复制到用户选择的本机目录。媒体 staging、同盘改名和数据库登记分步骤持久化，哈希一致后补登记；未知孤件隔离不删除。

默认导入复制。只接受白名单图片/音视频，经 ffprobe/解码核验后 available；证据文件首版限图片/音视频，文档授权可填写文字来源。路径检查针对实际目标及重解析点，SQL 的相对路径约束只是补充。源路径不进入 renderer DTO。

## 4. 资源保护与失败路径

初始工程保护值：JSON 1MiB、单媒体导入 2GiB、图片解码 40MP、ffprobe 单次 15s；这些是防误操作值，需 T02 实测后决定产品范围，不当硬件保证。导入前检查预计复制量+10%余量+256MiB；未知远程长度按适配器上限预留。大文件流式复制不整块入内存。

磁盘不足、权限、损坏库、锁占用、媒体 missing 各有独立错误。哈希不同的重新定位是“导入新素材并替换”，不能篡改旧 mediaId 内容。媒体缺失只影响引用它的对象。预算耗尽不阻止本地保存/导入。

## 5. 实现批次与验收

1. 项目创建/打开/短事务、全局创建恢复记录和只读锁。
2. 草稿保存、CAS、响应丢失查操作与真实保存反馈。
3. 媒体 staging/探测/流式 Range/重新定位和故障恢复。

| 示例 | 输入/操作 | 必须结果 |
| --- | --- | --- |
| V02-01 | 同一创建 operationId 重复两次 | 同一项目，一次目录创建；不同内容复用 ID 返回 409 |
| V02-02 | 改名后登记前终止进程 | 重开补登记匹配文件，哈希/媒体 ID 不变 |
| V02-03 | A 保存 revision=3；B 仍以 3 保存 | B 冲突，A 内容不丢，B 输入保留 |
| V02-04 | 移动整个项目再打开 | 相对媒体可用；第二窗口只读 |
| V02-05 | 选择同名不同哈希文件替换 missing | 拒绝当原媒体恢复，给新导入入口 |
| V02-06 | WAL 活动时迁移备份 | backup API 副本完整，旧库保留；损坏副本不继续迁移 |
