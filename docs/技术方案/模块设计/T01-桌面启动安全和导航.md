## 3. 前端界面与状态

六组导航保持“故事、视觉与分镜、镜头制作、声音与剪辑、检查与导出、项目工具”，首页与设置为独立入口。业务页面展示当前未开放说明，不能提供可执行的保存/生成按钮。示例内容必须标注演示。

| 状态 | 用户看到的内容 | 动作 |
| --- | --- | --- |
| starting | 正在启动本地服务 | 可浏览说明和关闭应用；已有重启操作不重复提交 |
| ready | 本地服务已连接 | 仅开放 capabilities 明确支持的操作 |
| disconnected | 本地服务连接中断，已暂停操作 | 重新连接观察或明确重启；不暗示业务已经失败 |
| failed | 启动/停止失败的安全中文原因 | 可重启时给重启；清理不明时说明需关闭应用后处理 |
| incompatible | 应用与本地服务版本不匹配 | 修复安装说明，禁止业务调用 |
| stopping | 正在关闭本地服务 | 禁用重启；停止确认不代表进程已经退出 |
| stopped | 服务已停止 | 首次启动或已确定的重启流程可创建新实例 |

最小走查尺寸 1280×800，支持键盘、可见焦点、错误文字和明确主动作。采用协议附录中的 RuntimeSnapshot 与 revision，晚到状态不覆盖新状态。

界面不接收端口和令牌。安全诊断可含版本、PID、耗时和错误码，**绝不包含令牌、令牌片段、Authorization 或 init 原文**；只记录认证成功/失败状态。

## 4. 确定的工程决策

- 前端 Electron + React + TypeScript，后端 FastAPI + Python，首版本机部署。
- Python 监督进程持有 Job Object，挂起创建 API、加入 Job 后恢复；API/FFmpeg 在 Job 内，监督进程在该 Job 外。Electron 无需原生 Job 绑定。
- 同一 Python 打包入口按 supervisor/api 两种 role 运行；只有 API 角色启动 Uvicorn、处理业务、访问未来数据库。
- 两层匿名管道采用有界 UTF-8 单行 JSON；令牌仅在 init 内存链路传递。消息、方向、序号及大小均有规范。
- GET /api/v1/health 和 /capabilities 是本模块全部 HTTP 业务入口；后者返回 12 个固定能力 ID，T01 只开放 runtime。
- 开发和生产均验证会话、精确 Host/Origin 及协议/构建版本；生产文档入口关闭。
- 进程事件按 child 对象、runtimeId、generation 隔离；所有状态变化串行，关闭意图优先于重启。
- PyInstaller 使用 onedir、console=True 保留标准流，由父进程隐藏窗口；后端放在 asar 外。
- 固定版本、锁文件与目录包已实测；升级时须重跑相应契约、进程及桌面检查。

上述决策的细节见附录，不再保留“开发者自行选择 Windows 绑定方式”的开放项。若实测推翻局部选择，应记录错误和替代方案并同步设计。

## 6. 验收矩阵

| 编号 | 场景 | 必须观察到的结果 |
| --- | --- | --- |
| A01 | 按 lockfile 干净安装与构建 | 精确依赖可重复；导出的契约与生成 TS 一致 |
| A02 | 自带 Python 的 Windows x64 目录包 | 中文/空格路径启动，标准流可用，无可见后端控制台 |
| A03 | 后端缺失、权限不足、启动超时 | 明确失败，不无限重启、不假 ready |
| A04 | 缺失/错误/上次实例令牌 | 接口拒绝，响应/日志/诊断不回显秘密 |
| A05 | 非法 Host、Origin、查询、请求体/方法 | 按协议拒绝，服务只监听实际 IPv4 回环 |
| A06 | renderer 尝试 require、任意 IPC/URL | 无能力执行，preload 不泄露原始 IPC 对象 |
| A07 | 非法导航、远程脚本、新窗口 | 阻止；预定义资料链接只交系统浏览器 |
| A08 | 主协议、控制协议、构建版本不符 | 清理后 incompatible，禁止业务 |
| A09 | API 崩溃，随后明确重启 | 旧实例失效，新代际连接，不自动发起业务 |
| A10 | 正常关闭、main/supervisor/API 分别退出 | 所属子进程清理，其他用户程序不受影响 |
| A11 | 双击重启、第二应用实例 | 同一重启合并，第二实例不启动第二业务后端 |
| A12 | 1280×800、键盘、未实现页面 | 焦点/主动作可见，未实现能力不冒称可用 |
| A13 | starting/failed/incompatible 时关闭 | 关闭意图优先，不因晚到 ready 再创建服务 |
| A14 | 旧代际 ready、健康响应、退出事件晚到 | 丢弃旧事件，新实例状态保持正确 |
| A15 | 分帧/UTF-8/超长/半帧/重复键/乱序 | 两端同样接受合法消息、终止不合法当前实例 |
| A16 | stop_ack 后进程仍存活 | 保持 stopping；Job 活动数归零和监督进程退出后才 stopped |
| A17 | 5 秒优雅退出超时 | 强制处理仅限当前 Job；无法确认清理时不启动下一代 |
| A18 | API mutex 已被占用 | 新实例失败，不杀原进程，不偷偷换端口启动 |
| A19 | 401、连续健康失败、存活实例恢复 | 按约定断开/重连，不把健康请求变成生成恢复提交 |
| A20 | 生产 docs/openapi、异常与秘密哨兵 | 文档入口关闭，所有错误和诊断均无秘密 |

pytest 验证后端 HTTP/协议与 Windows 集成；Vitest 验证前端 codec、状态与桥；Playwright 验证实际桌面和目录包。Windows 进程测试不能被 mock 或 skip 代替。启动时间、内存与体积记录实测，不预先承诺数值。
