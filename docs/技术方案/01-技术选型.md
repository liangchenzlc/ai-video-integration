# 技术选型

方案版本：0.3，2026-09-15。前端 **Electron + React + TypeScript**、后端 **FastAPI + Python** 由用户指定；其余为本次推荐的工程方案。项目尚无应用代码，准确候选版本见[工程基线](./契约/t01-toolchain-baseline.json)，已核对元数据；运行兼容性与 lockfile 在 T01-A 验证后锁定。

## 1. 架构选择与约束

采用前后端分离：前端与后端使用独立目录、依赖、构建和测试，通过版本化 HTTP API 通信。后端内部采用模块化单体，避免在业务尚未实现时引入多个服务。

结合[产品规格](../01-产品定位与功能规格.md)的 Windows 本地、BYOK、无应用账号与项目本地保存要求，首版按 **桌面应用附带本机后端** 设计：Electron 启动 Python 监督进程，监督进程管理仅监听回环地址的 FastAPI API 进程。用户无需安装 Python 或自行启动服务器。

前后端分离是代码和接口边界，不要求把后端部署到公网。远程部署涉及账户、TLS、多租户、存储和凭据托管，属于将来独立评估的产品范围。

| 约束 | 技术响应 |
| --- | --- |
| Windows 本地桌面 | Electron 外壳，打包 Python 后端，项目使用本机目录 |
| 前后端分别维护 | TypeScript 前端、Python 后端、OpenAPI 接口契约 |
| BYOK，无自有生成云后端 | Python 直接访问用户服务商，凭据本机加密，不设置自有代付服务 |
| 一个用户任务、有限候选串行 | SQLite 持久化任务 + 单执行器，不需要分布式队列 |
| 退出与断网后可恢复 | 提交前落盘，原任务查询，媒体与费用独立记录 |
| 图片、视频、声音及基础剪辑 | Python 调用 FFmpeg 子进程，长任务不阻塞 HTTP 请求 |
| 逐模块实施 | 每个模块纵向完成界面、API、业务和验证，后续模块只预留边界 |

## 2. 核心选型与比较

### 2.1 前端与后端

Electron、React、TypeScript、FastAPI 和 Python 已确定，不再对这些主框架另选方案。FastAPI 适合明确的数据模型、HTTP 接口和 OpenAPI 输出；Python 便于组织模型调用、文件与媒体任务。双运行时会增加安装体积、进程管理和打包复杂度，这些成本在 T01 提前验证。

前端不实现预算、版本采用、恢复协议等业务规则；后端不承担 React 页面渲染。Electron 主进程只处理桌面权限、后端生命周期和受控 HTTP 转发，保持桥接层轻量。

### 2.2 数据、任务与通信

| 事项 | 推荐方案 | 比较与理由 |
| --- | --- | --- |
| 项目数据库 | SQLite，Python 标准库 sqlite3 | 本地无需安装数据库，支持事务与一致备份；当前没有需要 PostgreSQL/MySQL 的共享服务场景 |
| 数据访问 | 参数化 SQL + 编号迁移脚本 + 仓储接口 | 事务和唯一约束显式可查；首版暂不增加 ORM 与自动生成迁移的复杂度 |
| HTTP 服务 | Uvicorn，单进程 | 与 FastAPI 配套；应用内只有一个任务执行器，多 worker 会破坏本地唯一执行前提 |
| 后台任务 | 持久化任务表 + 一个专用执行线程 | HTTP 快速返回任务 ID，长调用独立执行；FastAPI BackgroundTasks 不承担必须恢复的生成任务 |
| 前后端通信 | HTTP JSON + 有界轮询 | 易测试和恢复，足够支撑单任务进度；SSE/WebSocket 在确有高频交互需求时再引入 |
| API 类型 | FastAPI/Pydantic 生成 OpenAPI，再生成 TypeScript 类型 | 减少两端手写字段漂移；生成类型不替代后端运行时校验 |
| 媒体传输 | 后端流式接口 + Electron 私有媒体协议代理 | 支持 Range 和大文件；不用 Base64 JSON 搬运完整视频，不暴露任意本地文件 |

SQLAlchemy/Alembic 是后续数据访问复杂度提高时的备选，不与手写迁移同时维护。迁移方式如需调整，必须能读取既有 schema 历史和生成一致备份，不改变项目数据不变量。

## 4. 本机后端与打包方案

开发时前端和后端可独立启动、独立测试，通过开发监督器或 Electron 启动协议连接；开发入口也有会话认证，不将“开发模式”作为任意本机网页访问 API 的理由。

生产时 PyInstaller 使用 onedir，产物作为 electron-builder 的额外资源放在 asar 外。选择 onedir 是为了便于核查文件、启动和诊断，避免每次启动先解压完整 Python。安装目录只放程序资源，项目与应用配置写入用户数据目录。

Python 同一发行目录按 supervisor/api 两种 role 启动；只有 API 运行 Uvicorn，监督进程在 Job 外持有唯一长寿命句柄，API/媒体在 Job 内。PyInstaller 使用 onedir、console=True 保留标准流；Electron 使用参数数组、windowsHide 和受控工作目录，API 以 CREATE_NO_WINDOW 隐藏。动态端口由后端实际绑定回环地址时申请，会话令牌通过匿名管道传递，不放在命令行、URL、磁盘或日志中。后端退出只清理本实例拥有的进程，不按进程名结束用户其他 Python 程序。

T01 验证健康检查、协议版本、异常退出和打包启动；T13 再验证干净系统安装、完整资源、升级、签名和许可。用户初期自行选择兼容 FFmpeg，不直接把研究下载二进制打入正式安装包。

## 5. 数据与状态的选择理由

SQLite 是项目事实来源。JSON 用于不可变版本 payload、能力档案与请求快照；Markdown 是说明文档，不成为第二份可编辑业务数据。

| 数据 | 归属 | 存放规则 |
| --- | --- | --- |
| 项目、版本、任务、账目、时间线 | Python 后端 | 项目 SQLite；事务、唯一约束、外键、WAL、FULL |
| 原件、代理、输出 | Python 后端 | 项目相对路径、稳定 ID、哈希；原件保留 |
| 用户 Key、能力配置 | Python 后端 | 应用用户数据目录，DPAPI 密文与普通配置分离 |
| 后端会话令牌 | Electron main 与后端内存 | 每次启动重新生成；不传渲染层、不持久化 |
| 选中对象、面板、未提交表单 | React | 临时视图状态，不冒充已保存或已采用 |
| 用户选取文件的授权 | Electron main | 原生对话框给出范围，由受限桥转交后端 |

后端使用短生命周期 SQLite 连接，不跨请求线程共享同一个连接。项目内写入通过互斥和短事务串行，连接配置与迁移由统一存储入口落实。数据库事务不等待网络、媒体编码或用户输入。

金额用整数微元，时间用整数毫秒；帧率用有理数描述。费用结算、当前采用、检查有效性都由后端计算，前端展示同一查询结果。

## 6. 任务、模型与媒体边界

任务表先持久化授权、输入、预算占用和提交状态，再由专用执行器处理。HTTP 断开不取消已受理任务；后端重启从数据库恢复事实，绝不因超时或退出自动重发生成 POST。

服务商具体型号、地域、价格和质量状态统一引用[模型与成本](../03-模型接入与成本控制.md)。当前研究组合不能直接提升为生产组合，正式配音、口型、AI 音乐/音效及检查能力分别准入。

HTTPX 采用明确的连接/读取超时和流式上限，生成调用关闭透明重试；查询和原下载可以按原授权恢复。WebSocket 语音接口或 OSS SDK 只在具体模块验证需要后引入，不提前接入全部供应商生态。

FFmpeg 使用 Python subprocess 参数数组执行，shell=false；后端登记作业、输入和输出。探测尺寸/时长不等于内容质量通过。T09 统一时间线模型和预演编译，T12 在相同语义上完成正式输出及完整解码验证。

## 7. 版本锁定与准入

本轮已核对官方资料和依赖元数据并确定[准确候选基线](./契约/t01-toolchain-baseline.json)，尚未安装或构建。T01 按[工程实施方案](./模块设计/T01-工程实施与验证.md)验证并产出运行基线：

1. 确认受支持的 Electron、React、TypeScript、开发 Node、pnpm 和 Vite 组合。
2. 选择受支持的 Python 次版本，核对 FastAPI、Pydantic、Uvicorn、uv、PyInstaller 和 Windows 扩展兼容。
3. 记录 Electron 内嵌 Node/Chromium、Python、SQLite 库、Windows x64 和运行系统版本，开发解释器与打包解释器分别验证。
4. 分别锁定 pnpm-lock.yaml 与 uv.lock，以 frozen 安装重复构建；用户无需安装开发依赖管理器。
5. 验证打包后 OpenAPI/健康检查、会话认证、前后端版本匹配和退出清理，不能只测开发模式。
6. 纳入依赖来源、许可声明和更新策略；实际工程具备 Git 后与代码一同版本管理。

单个依赖不兼容时优先调整对应工具和版本，记录受影响边界；不同时维护两套后端框架或两套数据库。依赖升级按独立变更验证契约、启动、数据迁移和必要桌面流程。

## 8. 风险与验证位置

| 风险 | 应对 | 所属模块 |
| --- | --- | --- |
| Python 后端漏打包动态依赖或启动过慢 | onedir 探针、启动时间和体积基线、干净系统验证 | T01、T13 |
| 回环端口被网页或其他进程误用 | 动态端口、随机令牌、Host/Origin 校验、禁宽松 CORS | T01 |
| 双端字段与版本漂移 | 自动生成 OpenAPI/TS 类型、兼容检查和契约验证 | T01 起 |
| 单进程内重复执行、重启误提交 | 单执行器、数据库防重与崩溃窗口测试 | T04 |
| SQLite 锁、共享盘和迁移故障 | 本机目录约束、项目写锁、短事务、一致备份 | T02 |
| 预览与编码不一致 | 同一时间线快照、固定夹具、帧/音轨核对 | T09、T12 |
| DPAPI 或媒体许可不满足分发条件 | 能力缺口明确、凭据不明文降级、分发前来源和义务核验 | T03、T13 |
